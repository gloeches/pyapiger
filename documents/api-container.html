Guide: Running Your flask-api.py with Gunicorn in Docker (Python 3.7)

This document provides a step-by-step guide on how to containerize your flask-api.py application using Docker, specifically with Python 3.7 and Gunicorn as the WSGI server.

Prerequisites

  • Docker Desktop installed and running on your machine.
  • Your flask-api.py file.

Step 1: Organize Your Project

Create a new folder (e.g., my-flask-app-py37) and place your flask-api.py file inside it. 

my-flask-app-py37/
└── flask-api.py

Step 2: Create a requirements.txt File

Your Flask application requires Flask and will be served by gunicorn. Create a file named requirements.txt in the same directory.

requirements.txt 
Flask
gunicorn

Your project structure should now look like this:

my-flask-app-py37/
├── flask-api.py
└── requirements.txt

Step 3: Create the Dockerfile

The Dockerfile contains instructions for building your Docker image. Create a file named Dockerfile (no extension) in your project directory.

Dockerfile 
# Use an official Python 3.7 runtime as a parent image
FROM python:3.7-slim

# Set the working directory inside the container
WORKDIR /app

# Copy the requirements file into the container at /app
COPY requirements.txt .

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Copy the rest of the application code into the container at /app
COPY . .

# Make port 8000 available to the world outside this container (Gunicorn's default)
EXPOSE 8000

# Define the command to run your app with Gunicorn
# "flask-api:app" assumes your Flask app instance is named 'app' in flask-api.py
# -b 0.0.0.0:8000 binds Gunicorn to all network interfaces on port 8000
CMD ["gunicorn", "flask-api:app", "-b", "0.0.0.0:8000"]

Explanation of the Dockerfile:

  • FROM python:3.7-slim: Specifies the base image as a lightweight Python 3.7 runtime, as requested.
  • WORKDIR /app: Sets the working directory inside the container to /app.
  • COPY requirements.txt .: Copies your requirements.txt file into the container.
  • RUN pip install --no-cache-dir -r requirements.txt: Installs Flask and Gunicorn. --no-cache-dir reduces image size.
  • COPY . .: Copies your flask-api.py and any other project files into the container.
  • EXPOSE 8000: Informs Docker that the container will listen on port 8000, which is Gunicorn's default.
  • CMD ["gunicorn", "flask-api:app", "-b", "0.0.0.0:8000"]: This command starts Gunicorn.
    • flask-api:app: Tells Gunicorn to find the Flask application instance named app within the flask-api.py module.
    • -b 0.0.0.0:8000: Binds Gunicorn to all available network interfaces (0.0.0.0) on port 8000, making it accessible from outside the container.

Your final project structure:

my-flask-app-py37/
├── Dockerfile
├── flask-api.py
└── requirements.txt

Step 4: Build the Docker Image

Open a terminal or command prompt, navigate to your my-flask-app-py37 directory, and run the following command. This builds your Docker image and tags it. 

docker build -t my-flask-api-gunicorn-py37 .

The . at the end tells Docker to use the current directory as the build context.

Step 5: Run the Docker Container

Once the image is built, run it as a container: 

docker run -d -p 5000:8000 my-flask-api-gunicorn-py37
  • -d: Runs the container in detached mode (background).
  • -p 5000:8000: Maps port 5000 on your host machine to port 8000 in the container (where Gunicorn is listening).
  • my-flask-api-gunicorn-py37: The name of the image to run.

Step 6: Verify It's Running

Your Flask API should now be running inside a Docker container. Access it by opening a web browser and navigating to:

  • API Landing Page: http://localhost:5000/
  • Sample API Request: http://localhost:5000/api?value=10

You should see the HTML description and the JSON response, respectively, served from your containerized application.
