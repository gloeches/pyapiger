Project Documentation

Introduction

This document explains the components of a containerized Flask application. The application's configuration is dynamically generated at runtime based on environment variables, and it's designed to be flexible and easy to use with Docker.

config_generator.py

This script is responsible for generating the config.json file, which holds the application's configuration.


import os
import json

def generate_config():
    production_env = os.environ.get("PRODUCTION", "false").lower() == "true"
    api_port = os.environ.get("API_PORT", 5000)
    
    if production_env:
        config_data = {"DDBB-SERVER": "PRODUCTION", "API-PORT": api_port}
    else:
        config_data = {"DDBB-SERVER": "DEVELOPMENT", "API-PORT": api_port}
        
    with open("config.json", "w") as config_file:
        json.dump(config_data, config_file, indent=4)
    print(f"El puerto es {api_port}")    
    print(f"la compilación:  {production_env}")   
if __name__ == "__main__":
    print("Generating configuration file...")
    generate_config()

Explanation:

  • It reads the PRODUCTION environment variable. If it's set to "true", the DDBB-SERVER in config.json will be "PRODUCTION"; otherwise, it will be "DEVELOPMENT".
  • It reads the API_PORT environment variable. If it's not set, it defaults to 5000.
  • It writes the configuration to a file named config.json.

flask-api.py

This is the main Flask application file.


# flask-app.py
from flask import Flask, request
import json

# create a Flask instance
app = Flask(__name__)

# Load configuration from config.json
print(f"flask-api.py is opening config.json to load the configuration")   
with open('config.json') as config_file:
    config = json.load(config_file)

app.config.update(config)

# a simple description of the API written in html.
# Flask can print and return raw text to the browser. 
# This enables html, json, etc. 

description =   """
                <!DOCTYPE html>
                <head>
                <title>API Landing</title>
                </head>
                <body>  
                    <h3>A simple API using Flask</h3>
                    <p>DDBB-SERVER: {db_server}</p>
                    <p>API_PORT: {port}</p>
                    <a href="http://localhost:{port}/api?value=2">sample request</a>
                </body>
                """.format(db_server=app.config.get('DDBB-SERVER'), port=app.config.get('API-PORT'))
				
# Routes refer to url'
# our root url '/' will show our html description
@app.route('/', methods=['GET'])
def hello_world():
    # return a html format string that is rendered in the browser
	return description

# our '/api' url
# requires user integer argument: value
# returns error message if wrong arguments are passed.
@app.route('/api', methods=['GET'])
def square():
    if not all(k in request.args for k in (["value"])):
        # we can also print dynamically 
        # using python f strings and with 
        # html elements such as line breaks (<br>)
        error_message = (
            f"Required paremeters : 'value'<br>"
            f"Supplied paremeters : {[k for k in request.args]}"
        )
        return error_message
    else:
        # assign and cast variable to int
        value = int(request.args['value'])
        # or use the built in get method and assign a type
        # http://werkzeug.palletsprojects.com/en/0.15.x/datastructures/#werkzeug.datastructures.MultiDict.get
        value = request.args.get('value', type=int)
        return json.dumps({"Value Squared" : value**2})

if __name__ == "__main__":
	# for debugging locally
	# app.run(debug=True, host='0.0.0.0',port=app.config.get('API-PORT'))
	
	# for production
	app.run(host='0.0.0.0', port=app.config.get('API-PORT'))

Explanation:

  • It's a simple Flask application with two routes: / and /api.
  • It reads the config.json file to get its configuration.
  • The / route displays a simple HTML page with the current DDBB-SERVER and API-PORT.
  • The /api route takes a value argument and returns its square in JSON format.
  • The application runs on the host and port specified in the config.json file.

Dockerfileflask

This file contains the instructions to build the Docker image for the application.


# Use an official Python 3.13 runtime as a parent image
FROM python:3.13-slim

# Set the working directory inside the container
WORKDIR /app

# Add a build-time argument for the port
ARG port=5000

# Copy the requirements file into the container at /app
COPY requirements.txt .

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt
RUN pip install --upgrade pip

# Copy the rest of the application code into the container at /app
COPY . .

# Make the entrypoint script executable
RUN chmod +x entrypoint.sh

# Make port available to the world outside this container
EXPOSE $port

# Set the entrypoint
ENTRYPOINT ["./entrypoint.sh"]

# Define the command to run your app
CMD ["python", "flask-api.py"]

Explanation:

  • FROM python:3.13-slim: Specifies the base image for the container.
  • WORKDIR /app: Sets the working directory inside the container to /app.
  • ARG port=5000: Defines a build-time argument for the port with a default value of 5000.
  • COPY requirements.txt .: Copies the requirements.txt file to the container.
  • RUN pip install --no-cache-dir -r requirements.txt: Installs the Python dependencies.
  • COPY . .: Copies the rest of the application code to the container.
  • RUN chmod +x entrypoint.sh: Makes the entrypoint.sh script executable.
  • EXPOSE $port: Informs Docker that the container listens on the specified port at runtime.
  • ENTRYPOINT ["./entrypoint.sh"]: Sets the entrypoint for the container. This command will always be executed when the container starts.
  • CMD ["python", "flask-api.py"]: Provides the default command to be executed by the entrypoint.

entrypoint.sh, ENTRYPOINT, and CMD

The entrypoint.sh script is the key to running the configuration generator before the main application.


#!/bin/sh
# entrypoint.sh

# Run the config generator
python config_generator.py

# Now, execute the command passed to this script (the Dockerfile's CMD)
exec "$@"

ENTRYPOINT vs. CMD

In Docker, ENTRYPOINT and CMD are two instructions that define what command is executed when a container is started. They can be used together or separately.

  • ENTRYPOINT: Specifies the main command that is always executed when the container starts. It's not meant to be overridden often.
  • CMD: Provides default arguments for the ENTRYPOINT. The CMD can be easily overridden from the `docker run` command line.

How They Work Together in This Project

In this project, we use both ENTRYPOINT and CMD to ensure that the configuration is always generated before the application starts.

  1. When the container starts, Docker executes the ENTRYPOINT, which is ./entrypoint.sh.
  2. The entrypoint.sh script first runs python config_generator.py to create the config.json file.
  3. The last line of the script is exec "$@". This is a special shell command that replaces the current process (the script itself) with the command passed as arguments to the script. In this case, the arguments are the contents of the CMD instruction from the Dockerfile, which is ["python", "flask-api.py"].
  4. So, after the config is generated, the script executes python flask-api.py, and the Flask application starts.

This pattern is very useful for running initialization tasks before starting the main application in a container.

How to Build and Run the Docker Container

Build the Image

To build the Docker image, run the following command in the same directory as the Dockerfileflask:

docker build -f Dockerfileflask -t gloeches/flask-api:01.00 .

If you want to expose a different port, you can use the --build-arg flag:

docker build -f Dockerfileflask --build-arg port=8080 -t gloeches/flask-api:01.00 .

Run the Container

To run the container, use the following command:

docker run -d --name flask-dev -p 2000:2000 -e API_PORT=2000 gloeches/flask-api:01.00

Explanation of the `docker run` command:

  • -d: Runs the container in detached mode.
  • --name flask-dev: Assigns the name "flask-dev" to the container.
  • -p 2000:2000: Maps port 2000 on the host to port 2000 in the container.
  • -e API_PORT=2000: Sets the API_PORT environment variable inside the container to 2000.
  • gloeches/flask-api:01.00: The name of the image to run.
